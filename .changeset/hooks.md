Run the hooks of Claude Code's `settings.json` at points of every run, and read a workspace's `AGENTS.md` and `CLAUDE.md` into the agent's system prompt.

Both are off by default: without `hooks` and `instructions.projectFiles` a run does what it did before. The breaking changes concern middleware written against `afterRun`.

Breaking:

- `afterRun` is now called for every run that ends: completed, paused and failed (an abort among them), not only for completed runs. `RunEndEvent` is `FinishedRunEnd | FailedRunEnd`: `event.status` is `completed` or `paused` with `event.result`, or `failed` with `event.error` and no result. Migration: a hook that keeps memory in shape or reads the result starts with `if (event.status !== 'completed') return` and reads `event.result` after it. The built-in extraction, compaction and memory upkeep do exactly that. An error an `afterRun` hook throws was already logged rather than failing the run, and still is.
- `beforeRun` may return `{ context }` (it returned nothing before), so code that calls a middleware's `beforeRun` itself and types its result as `void` adjusts.
- `PermissionDecider` has a new value, `hook`, for decisions a `PreToolUse` or `PermissionRequest` hook (or a `beforeToolCall` or `decideApproval` middleware) made: a `switch` over `decidedBy` handles it.

New:

- `CogitatorConfig.hooks: { hooks?, settings?, promptModel?, mcp?, allowedHttpHookUrls?, httpHookAllowedEnvVars?, maxOutputBytes?, onHookRun? }`. `hooks` takes the `hooks` of a settings file in code, `settings: true` (or `{ root, userDirs, managedDirs, layers, trusted }`) reads them from the files the permission rules come from: managed, user, project and local, `.claude/` and `.cogitator/`. A project's own files run only with `trusted: true` (or `permissions.settings.trusted: true`), so a cloned repository does not run its hooks on your machine. Hooks of every layer add up, a handler in several files runs once, `disableAllHooks` and `allowManagedHooksOnly` work as in Claude Code, files are read again once they change.
- Events: `SessionStart` and `SessionEnd` (a run is a session), `UserPromptSubmit`, `PreToolUse`, `PermissionRequest`, `PostToolUse`, `PostToolUseFailure`, `PostToolBatch`, `SubagentStart` and `SubagentStop` (for runs started from another run's tool call), `PreCompact`, `PostCompact`, `PreModelSwitch` (a handoff to an agent on another model), `Stop` and `Notification`. Matchers are Claude Code's (exact names, `|` lists, regular expressions), tool events match the tool's name, its MCP name and the Claude Code names that cover it (`Bash` for `run_command`), and a handler's `if` takes one permission rule.
- Handlers: `command` (the event's JSON on stdin and never on the command line, exec form with `args` or `/bin/sh -c`, the project root as working directory, `CLAUDE_PROJECT_DIR` and `COGITATOR_PROJECT_DIR` set, the process environment without `OTEL_*`, a process group of its own killed at the `timeout`, stdout and stderr read up to `maxOutputBytes`, `async`), `http` (a POST to its URL only, redirects not followed, `allowedHttpHookUrls`, header variables only from `allowedEnvVars`), `prompt` (a model asked for `{ ok, reason }`, schema checked, its cost in the run's usage) and `mcp_tool` (through `hooks.mcp`, skipped with a warning without it). Exit code 2 blocks with stderr as the reason, other codes let the action go on, `onFailure: 'block'` turns a failure into a block, and the JSON output fields (`continue`, `stopReason`, `systemMessage`, `decision`, `reason`, `hookSpecificOutput` with `permissionDecision`, `updatedInput`, `additionalContext`, `updatedToolOutput`, the `PermissionRequest` `decision`) mean what they mean in Claude Code.
- `PreToolUse` runs before the permission rules: `deny` refuses, `ask` asks, `allow` skips an approval only the mode or the tool would ask for (an `ask` or `deny` rule still applies), `defer` pauses the run and the hook runs again on resume, `updatedInput` is checked against the schema and decided by the rules. `PermissionRequest` answers an approval before `onApproval`. Both are logged with `decidedBy: 'hook'`. Every handler run is saved to the thread as a `custom` entry `{ kind: 'hook', ... }` and reported to `onHookRun` (`HookRunRecord`). The docs list the differences from Claude Code.
- New middleware hooks, which the hooks are built on: `startRun`, `beforeToolCall`, `decideApproval`, `afterToolBatch`, `beforeStop`, `beforeCompaction`, `afterCompaction`, `beforeModelSwitch` and `onNotification`, and `{ context }` from `beforeRun`. `RunMiddlewareContext` gets `parentRunId`, `permissionMode`, `addContext(text)` (a system message for the next model call, saved to the thread), `stop(reason)` (the run completes with `result.stopped: { reason, middleware }`) and `logEvent(event, note)`. The compactions of `context` and `memory.compaction` ask `beforeCompaction` first.
- `CogitatorConfig.instructions.projectFiles: true | { files?, rules?, nested?, maxImportDepth?, allowImportsFrom?, maxChars? }` reads `AGENTS.md`, `CLAUDE.md`, `.claude/CLAUDE.md` and `CLAUDE.local.md` from the workspace root down to its `cwd` into the system prompt, each file once, with `@path` imports (relative to the file, at most 4 hops, cycles stopped, inside the workspace unless `allowImportsFrom` allows a directory), the rules of `.claude/rules/` (with `paths` frontmatter they join the conversation once a tool reads or edits a matching file, as do the files of deeper directories) and a 32 000 character limit with a notice of what was cut. `RunResult.instructions` and `RunCheckpoint.instructions` list the files (`LoadedInstructionFile`), and the thread's log gets a `custom` entry `{ kind: 'instructions', files }`.
- `@cogitator-ai/core` exports `hooksMiddleware`, `loadHookSettings`, `readHookSettings`, `compileMatcher`, `readStdout`, `STOP_HOOK_CONTINUATION_CAP`, `ruleMatchesCall`, `hookNamesOf`, `ProjectInstructionsLoader`, `instructionPathsIn` and the instruction defaults. `@cogitator-ai/types` adds `HooksConfig`, `HookSettings`, `HookMatcherGroup`, `HookHandlerConfig` and its four handler types, `HookEventName`, `HOOK_EVENTS`, `HookRunRecord`, `HookMcpCaller`, `HookSettingsOptions`, `InstructionsConfig`, `ProjectInstructionsOptions`, `LoadedInstructionFile` and the events of the new middleware hooks.
