Memory works between runs, not only while a run builds its context. A brief hands a turn a few cards of what memory holds for it, each quoting its source, observations keep what memory makes of each entity next to the facts, and a consolidation pass in the background marks repeats stale and folds lessons into a playbook a few edits at a time. Every piece asks a model and checks what it answers before anything is kept, and all of them are off unless set.

- Core: `memory.brief` (`model`, `maxCards` from 1 to 4, `timeoutMs` 4000, `maxTokens` 600, `prompt`). Before the first model call of a run a cheap model reads the 12 best sources memory finds for the input, earlier turns of the run's branch and the memory items the run sees, ranked as `hybrid` recall ranks them, and writes cards, each a `constraint`, `knowledge`, a `consequence` or an `open_thread` quoting its source. Only cards whose quote the source holds word for word, spacing and case aside, go into the turn's memory context, marked as a hint and never into the system message. A timeout, a failure, a run without memory or nothing found leaves the turn as it was. `memoryBriefMiddleware(config, deps)` is the middleware behind it.
- Core: `memory.observations` (`model`, `maxEntities` 3, `minItems` 3, `prompt`). After a run, in the background, the observations whose facts changed are written again as memory files under `/memories/observations/`, each statement citing the items it stands on, and a turn whose input names an entity, or that recalls one of its items, gets up to three of them next to the facts.
- Core: `memory.consolidation` (`model`, `everyRuns` 20, `afterCompaction` true, `maxChanges` 10, `maxSubjects` 10, `playbook` `apply`, `shadow` or `false`, `showPlaybook` true, `prompt`, `afterConsolidate`). Every `everyRuns` runs of a thread, and after `memory.compaction` compacted it (a compaction that changed nothing starts none), a pass marks as stale the items a model finds to repeat or contradict a newer one, asking about at most `maxSubjects` subjects, the oldest first, and going on where it stopped the next time, folds new `active` lessons into `/memories/playbook.md` in at most three edits, then writes the observations. Every run then sees the playbook in its memory context as a hint, up to 4000 characters. Passes run in the background one at a time per memory scope, no run waits for them, their model calls count in the cost router but not in a run's usage, and `close()` stops the passes under way. `memoryUpkeepMiddleware(config, deps)` is the middleware behind observations and consolidation, `upkeepScope` the scope memory items of a run belong to, and `CONSOLIDATION_STATE` the thread metadata key that counts runs.
- Core: `Cogitator.consolidateMemory(agent, { userId?, threadId? })` runs a pass now, such as from a worker while the agent is idle, and returns what it changed. It throws `VALIDATION_ERROR` when neither `memory.consolidation` nor `memory.observations` is set, or without a `userId` (a `threadId` for the memory of runs without a user).
- Memory: `MemoryBriefer` writes the cards of a brief from a model's answer, keeping only those whose quote holds (`parseBrief`, `briefBlock`, `BRIEF_PROMPT`, `MAX_BRIEF_CARDS`).
- Memory: `MemoryObservations` keeps observations of entities as memory files (`refresh`, `read`), each with a fingerprint of the items it was written from, so it is written again only once they change, and deleted once its entity has fewer than `minItems` facts that hold. A statement naming an item the model was not given is dropped, and facts that gave no observation are not asked about again in the process until they change. `ContextBuilderDeps.observations` shows them to a turn.
- Memory: `MemoryConsolidator` consolidates one scope's memory. `dedupe` marks as stale (never deletes) the items of exactly the scope a model groups as repeating or contradicting another one about the same entity, never an item more trusted than the one kept and, for a contradiction, only items said before it, with the reason in `metadata.staleBecause`, and returns `{ stale, complete, through? }`, `through` saying where a later dedupe that a cap stopped goes on `since`. `foldLessons` folds `active` lessons, oldest first and 20 a fold, into the playbook in at most three edits, so a lesson a model, a tool or a page wrote stays out until `MemoryItems.activate` makes it `active`, and an answer the model did not finish folds nothing, each adding a rule or rewriting one rule, so the playbook is never written over whole, every fold a new version of the file. With `mode: 'shadow'` the edited playbook goes to `/memories/playbook.next.md`, and `promotePlaybook` makes it the playbook only when the playbook did not change since.
- Memory: `MemoryFiles.put(access, path, text, expectedSha256?)` writes a whole file, created when it does not exist, failing when the file no longer stands as the caller read it. `MemoryItems.markStale(itemIds, because?, onlyFrom?)` keeps `because` in the items' `metadata.staleBecause`, and with `onlyFrom` leaves an item whose status is no longer one of those as it is. `inert` is exported.
- Config: `MemoryBriefConfigSchema`, `MemoryObservationsConfigSchema` and `MemoryConsolidationConfigSchema` validate `memory.brief`, `memory.observations` and `memory.consolidation`.
- Types: `MemoryBriefConfig`, `BriefCard`, `BriefCardKind`, `MemoryObservationsConfig`, `MemoryConsolidationConfig`, `MemoryConsolidationReport`, `StaleMark`, `MemoryConfig.brief`, `MemoryConfig.observations` and `MemoryConfig.consolidation`, `RunMiddlewareContext.memoryAgentId`, and `observations` among the sources of `ContextBuildError`.
