Workflow state types must satisfy `WorkflowState` (`Record<string, unknown>`): use a type alias or `interface MyState extends WorkflowState`.

## Building and Running

```typescript
import {
  WorkflowBuilder,
  WorkflowExecutor,
  agentNode,
  functionNode,
} from '@cogitator-ai/workflows';
import type { WorkflowState } from '@cogitator-ai/types';

interface ReportState extends WorkflowState {
  topic?: string;
  draft?: string;
  words?: number;
}

const workflow = new WorkflowBuilder<ReportState>('report')
  .initialState({ topic: 'WebAssembly' })
  .addNode(
    'write',
    agentNode<ReportState>(writer, {
      inputMapper: (state) => `Write a short report about ${state.topic}`,
      stateMapper: (result) => ({ draft: result.output }),
    })
  )
  .addNode(
    'count',
    functionNode<ReportState>('count', async (state) => state.draft?.split(/\s+/).length ?? 0, {
      stateMapper: (words) => ({ words: words as number }),
    }),
    { after: ['write'] }
  )
  .build();

const result = await new WorkflowExecutor(cog).execute(workflow);
console.log(result.state.words, result.error);
```

### `WorkflowBuilder<S>`

| Method           | Signature                                                                                                              | Purpose                                        |
| ---------------- | ---------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------- |
| constructor      | `new WorkflowBuilder<S>(name: string)`                                                                                 |                                                |
| `initialState`   | `initialState(state: S): this`                                                                                         | Default state, merged with the execution input |
| `addNode`        | `addNode(name: string, node: NodeFn<S> \| WorkflowNode<S>, options?: { after?: string[]; config?: NodeConfig }): this` | Add a node function or a factory-made node     |
| `addConditional` | `addConditional(name: string, condition: (state: S) => string \| string[], options?: { after? }): this`                | Route to the node(s) `condition` names         |
| `addLoop`        | `addLoop(name: string, options: { condition: (state: S) => boolean; back: string; exit: string; after? }): this`       | Loop back while `condition` holds              |
| `addParallel`    | `addParallel(name: string, targets: string[], options?: { after? }): this`                                             | Fan out to several nodes                       |
| `entryPoint`     | `entryPoint(nodeName: string): this`                                                                                   | Set the entry point explicitly                 |
| `build`          | `build(): Workflow<S>`                                                                                                 | Validate and compile                           |

`NodeFn<S>` is `(ctx: NodeContext<S>) => Promise<NodeResult<S>>` with `ctx = { state, input?, nodeId, workflowId, step, reportProgress? }` and `NodeResult = { state?: Partial<S>; output?; next? }`. `NodeConfig` is `{ timeout?, retries?, retryDelay? }`. `build()` throws when there is no single root (independent roots need a root `addParallel` or `.entryPoint()`) and when a node after a loop is neither its `back` nor its `exit` node. See [Builder](/docs/workflows/builder).

### `WorkflowExecutor`

| Method      | Signature                                                                                                              | Purpose                                                                                                           |
| ----------- | ---------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------- |
| constructor | `new WorkflowExecutor(cogitator: Cogitator, checkpointStore?: CheckpointStore)`                                        | Default store: `InMemoryCheckpointStore`                                                                          |
| `execute`   | `execute<S>(workflow: Workflow<S>, input?: Partial<S>, options?: ExecutorExecuteOptions): Promise<WorkflowResult<S>>`  | Run to completion; a failure lands in `result.error`                                                              |
| `resume`    | `resume<S>(workflow: Workflow<S>, checkpointId: string, options?: WorkflowExecuteOptions): Promise<WorkflowResult<S>>` | Continue from a checkpoint, skipping completed nodes                                                              |
| `stream`    | `stream<S>(workflow, input?, options?): AsyncIterable<StreamingWorkflowEvent>`                                         | Events: `workflow_started`, `node_started`, `node_progress`, `node_completed`, `node_error`, `workflow_completed` |

`ExecutorExecuteOptions` extends `WorkflowExecuteOptions`:

| Option                                                           | Purpose                                              |
| ---------------------------------------------------------------- | ---------------------------------------------------- |
| `maxConcurrency`, `maxIterations`                                | Parallel nodes, loop safety limit                    |
| `checkpoint`, `checkpointStrategy`                               | Save checkpoints (`'per-iteration'` or `'per-node'`) |
| `onNodeStart`, `onNodeComplete`, `onNodeError`, `onNodeProgress` | Callbacks                                            |
| `workflowId`, `skipNodes`, `nodeResults`                         | Identity and resumption                              |
| `signal`                                                         | Cancel the run                                       |
| `tracer`, `metricsCollector`                                     | [Observability](#observability)                      |
| `defaultRetry`, `defaultCircuitBreaker`                          | Saga defaults for every node                         |
| `deadLetterQueue`, `idempotencyStore`                            | Saga infrastructure                                  |
| `approvalStore`, `approvalNotifier`, `timerStore`                | Stores for human and timer nodes                     |
| `depth`                                                          | Subworkflow nesting depth                            |

`WorkflowResult<S>`: `{ workflowId, workflowName, state, nodeResults: Map<string, { output, duration }>, duration, checkpointId?, error? }`. `NodeExecutionError` (`nodeName`) and `NodeTimeoutError` (`nodeName`, `timeoutMs`) are the errors nodes fail with. `WorkflowScheduler` is the executor's internal DAG scheduler (dependency graph, ready nodes, concurrency), exported for custom executors. See [Execution](/docs/workflows/execution).

## Nodes

| Export                     | Signature                                                                                                                                     | Purpose                                             |
| -------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------- |
| `agentNode`                | `agentNode<S>(agent: Agent, options?: { inputMapper?; stateMapper?: (result: RunResult) => Partial<S>; runOptions? }): WorkflowNode<S>`       | Run an agent                                        |
| `toolNode`                 | `toolNode<S, TArgs>(tool: Tool<TArgs>, options: { argsMapper: (state: S, input?) => TArgs; stateMapper?; signal? }): WorkflowNode<S>`         | Run a tool                                          |
| `functionNode`             | `functionNode<S, O>(name: string, fn: (state: S, input?) => Promise<O>, options?: { stateMapper?: (output) => Partial<S> }): WorkflowNode<S>` | Run a function                                      |
| `customNode`               | `customNode<S>(name: string, fn: (ctx: NodeContext<S>) => Promise<NodeResult<S>>): WorkflowNode<S>`                                           | Full control over state, output and `next`          |
| `humanWorkflowNode`        | `humanWorkflowNode<S>(config: HumanNodeConfig<S>, options?: { approvalStore?; approvalNotifier?; stateMapper? }): WorkflowNode<S>`            | Wait for a person (see [Human](#human-in-the-loop)) |
| `timerWorkflowNode`        | `timerWorkflowNode<S>(config: AnyTimerNodeConfig<S>, options?: { timerStore?; stateMapper? }): WorkflowNode<S>`                               | Wait for a delay, date or cron time                 |
| `mapWorkflowNode`          | `mapWorkflowNode<S, T>(config: MapNodeConfig<S, T>, options?: { stateMapper? }): WorkflowNode<S>`                                             | Process items in parallel                           |
| `mapReduceWorkflowNode`    | `mapReduceWorkflowNode<S, T, R>(config: MapReduceNodeConfig<S, T, R>, options?: { stateMapper? }): WorkflowNode<S>`                           | Map, then reduce                                    |
| `subworkflowWorkflowNode`  | `subworkflowWorkflowNode<PS, CS>(config: SubworkflowConfig<PS, CS>, options?: { checkpointStore? }): WorkflowNode<PS>`                        | Run a nested workflow                               |
| `parallelSubworkflowsNode` | `parallelSubworkflowsNode<S>(config: ParallelSubworkflowsConfig<S>, options?: { checkpointStore? }): WorkflowNode<S>`                         | Run nested workflows in parallel                    |

The `*WorkflowNode` adapters turn the configs built by the helpers below (`approvalNode`, `delayNode`, `mapNode`, `subworkflowNode`, …) into nodes for `addNode`. See [Nodes](/docs/workflows/nodes).
