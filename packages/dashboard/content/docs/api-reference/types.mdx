`@cogitator-ai/types` holds the shared interfaces of every package. Most of the types below are also re-exported from `@cogitator-ai/core`. Comments mark defaults and behaviour; the definitions are trimmed of doc comments, not of fields.

## Agent Types

```typescript
interface AgentConfig<TDeps = unknown> {
  id?: string;
  name: string;
  description?: string;
  provider?: string; // explicit provider, e.g. 'openai' for an OpenAI-compatible server
  model?: string; // 'provider/model'; falls back to llm.defaultModel of the Cogitator
  fallbackModels?: FallbackModel[]; // tried in order when model fails, see LLM Backends
  instructions: string;
  tools?: Tool<unknown, unknown, TDeps>[]; // with TDeps set, only tools whose deps it provides
  skills?: Skill[];
  temperature?: number; // Agent default: 0.7
  topP?: number;
  maxTokens?: number;
  stopSequences?: string[];
  responseFormat?: ResponseFormat;
  reasoning?: ReasoningConfig;
  handoffs?: Array<Agent | Handoff>; // each becomes a transfer_to_<name> tool
  maxIterations?: number; // Agent default: 10
  timeout?: number; // ms; run default: limits.defaultTimeout, else 120000
  middleware?: RunMiddleware<TDeps>[]; // hooks around its model and tool calls
}

type FallbackModel = string | { model: string; provider?: string };

interface ModelFallbackEvent {
  from: string; // 'provider/model' that failed
  to: string; // 'provider/model' the turn goes on with
  error: Error; // its error, or CIRCUIT_OPEN when it was skipped
}

interface ModelCircuitBreakerConfig {
  failureThreshold?: number; // failures in a row before a model is skipped, default 5
  resetTimeout?: number; // ms a failing model is skipped, default 30000
  halfOpenRequests?: number; // successes needed afterwards, default 3
}

// deps as a run must pass them: required when the agent declares its deps type
type RunDeps<TDeps> = unknown extends TDeps ? { deps?: unknown } : { deps: TDeps };

interface Handoff {
  agent: Agent;
  toolName?: string; // instead of transfer_to_<agent name>
  description?: string; // defaults to the agent's description
}

type ResponseFormat =
  { type: 'text' } | { type: 'json' } | { type: 'json_schema'; schema: ZodType };

interface Agent {
  readonly id: string;
  readonly name: string;
  readonly config: AgentConfig;
  readonly model: string | undefined;
  readonly instructions: string;
  readonly tools: Tool[];
  clone(overrides: Partial<AgentConfig>): Agent;
  serialize(): AgentSnapshot;
}

interface DeserializeOptions {
  toolRegistry?: { get(name: string): Tool | undefined };
  tools?: Tool[];
  overrides?: Partial<AgentConfig>;
}
```

`AgentSnapshot` (`{ version, id, name, config: SerializedAgentConfig, metadata? }`) is the JSON form `agent.serialize()` produces, tools are kept by name.

`AgentWireConfig` is how an agent travels to another process (`toAgentWire` / `fromAgentWire` in `@cogitator-ai/core`): every `AgentConfig` field, tools as `ToolSchema`s, the response schema as JSON Schema (`AgentWireResponseFormat`), handoffs as `AgentWireHandoff`s naming agents carried in `handoffAgents`. `AgentWireRunResult` is a run's outcome on the wire: `output`, `structured`, `structuredError`, `reasoning`, `usage` (`AgentWireUsage`: tokens, `cost`, `duration`, reasoning and cache tokens), `toolCalls` (`AgentWireToolCall`: `name`, `input`, `output`), `truncated`, `blocked`, `iterationLimitReached`, `modelUsed`, `handoffs`, `finalAgent`, `runId` and `threadId`.

## Run Types

```typescript
interface RunOptions<TDeps = unknown> {
  input: string;
  images?: ImageInput[]; // URLs, base64 or { data, mimeType }
  audio?: AudioInput[]; // transcribed and added to the input
  context?: Record<string, unknown>; // sent as data in the turn context, in front of the input
  deps?: TDeps; // tools get them as context.deps; never sent to the model, memory or checkpoints
  threadId?: string;
  timeout?: number;
  signal?: AbortSignal;
  stream?: boolean; // streams only together with onToken
  onToken?: (token: string) => void;
  onReasoning?: (delta: string) => void;
  onHandoff?: (handoff: HandoffEvent) => void;
  onModelFallback?: (event: ModelFallbackEvent) => void; // { from, to, error }
  onModelTurn?: (turn: KeptModelTurn) => void; // { content, toolCalls, model } after afterModel
  reasoning?: ReasoningConfig; // overrides the agent's
  onApproval?: (
    request: ToolApprovalRequest
  ) => ToolApprovalDecision | 'pause' | Promise<ToolApprovalDecision | 'pause'>;
  onToolCall?: (call: ToolCall) => void;
  onToolResult?: (result: ToolResult) => void;
  useMemory?: boolean; // default: true when an adapter is configured
  loadHistory?: boolean; // default: true
  saveHistory?: boolean; // default: true
  onRunStart?: (data: { runId: string; agentId: string; input: string; threadId: string }) => void;
  onRunComplete?: (result: RunResult) => void;
  onRunError?: (error: Error, runId: string, usage?: RunUsage) => void;
  onSpan?: (span: Span) => void;
  onMemoryError?: (error: Error, operation: 'save' | 'load') => void;
  branch?: { fromEntryId: string | null; activate?: boolean }; // run on a branch of the thread, activate default: true
  brief?: string; // notes for this turn only, sent with the input and not saved
  parallelToolCalls?: boolean; // default: false
  middleware?: RunMiddleware<TDeps>[]; // after the Cogitator's and the agent's, pass again to resume()
  userId?: string; // owns new threads, scopes facts, reaches tools as context.userId
  threadAccess?: 'owner' | 'shared'; // default: 'owner'
  channelType?: string;
  channelId?: string;
}

interface RunResult {
  readonly output: string;
  readonly structured?: unknown;
  readonly runId: string;
  readonly agentId: string;
  readonly threadId: string;
  readonly modelUsed?: string; // model of the final answer, set with cost routing or a fallback
  readonly usage: {
    readonly inputTokens: number;
    readonly outputTokens: number;
    readonly totalTokens: number;
    readonly cost: number;
    readonly duration: number;
    readonly reasoningTokens?: number;
    readonly cachedInputTokens?: number;
    readonly cacheWriteTokens?: number;
  };
  readonly reasoning?: string;
  readonly truncated?: boolean; // the last answer stopped at maxTokens
  readonly blocked?: 'content_filter' | 'refusal'; // the last answer was filtered or refused
  readonly prompt?: RunPrompt; // the instruction version or A/B variant used
  readonly handoffs?: readonly HandoffEvent[];
  readonly finalAgent?: string;
  readonly status?: 'completed' | 'paused';
  readonly pendingApprovals?: readonly ToolApprovalRequest[];
  readonly checkpoint?: RunCheckpoint;
  readonly toolCalls: readonly ToolCall[];
  readonly messages: readonly Message[];
  readonly trace: { readonly traceId: string; readonly spans: readonly Span[] };
  readonly reflections?: readonly Reflection[];
  readonly reflectionSummary?: ReflectionSummary;
  readonly memory?: RunMemoryPlace; // where the run wrote in memory, when it wrote anything
}

interface RunMemoryPlace {
  readonly threadId: string;
  readonly branchPoint: string | null; // the entry the run's first entry went after
  readonly leafId?: string; // the run's last entry
}

interface HandoffEvent {
  from: string;
  to: string;
  reason?: string;
}
```

```typescript
  RunOptions,
  'input' | 'images' | 'audio' | 'context' | 'threadId' | 'threadAccess'

  userId?: string;
  decisions?: Record<string, ToolApprovalDecision>; // by tool call id
  defaultDecision?: ToolApprovalDecision; // for every call decisions leaves out

  save(checkpoint: RunCheckpoint): Promise<void>;

```

`RunCheckpoint` is the plain-JSON state of a paused run (`version: 1`, `runId`, `threadId`, `model`, `messages`, the paused `turn` with its decisions, usage so far, `branch` (where a run on a branch writes next), …) that `cogitator.resume()` continues from.

### Middleware

```typescript
interface RunMiddleware<TDeps = unknown> {
  readonly name: string;
  readonly holdsStream?: boolean; // a streamed turn's text waits until the turn is done
  beforeRun?(event: RunInputEvent, context: RunMiddlewareContext<TDeps>): void | Promise<void>;
  beforeModel?(
    event: ModelTurnEvent,
    context: RunMiddlewareContext<TDeps>
  ): void | ModelTurnUpdate | Promise<void | ModelTurnUpdate>;
  wrapModelCall?(
    call: ModelCallRequest,
    next: (call: ModelCallRequest) => Promise<ChatResponse>,
    context: RunMiddlewareContext<TDeps>
  ): Promise<ChatResponse>;
  afterModel?(
    event: ModelResponseEvent,
    context: RunMiddlewareContext<TDeps>
  ): void | ModelResponseUpdate | Promise<void | ModelResponseUpdate>;
  wrapToolCall?(
    call: ToolCallRequest,
    next: (call: ToolCallRequest) => Promise<ToolResult>,
    context: RunMiddlewareContext<TDeps>
  ): Promise<ToolResult>;
  afterRun?(event: RunEndEvent, context: RunMiddlewareContext<TDeps>): void | Promise<void>;
}

interface RunEndEvent {
  readonly result: RunResult;
  readonly model: string; // the model the run ended on, as provider/model
  readonly memoryAgentId: string; // the id the agent's memory items are kept under: its configured id, else its name
}

interface ModelCallRequest {
  request: ChatRequest;
  model: string; // provider/model the call goes to
  stream?: { onToken(token: string): void; onReasoning?(delta: string): void };
}

interface ToolCallRequest {
  toolCall: ToolCall; // as the model made it
  tool: Tool;
  args: unknown; // as the tool's schema parsed them
  approved: boolean; // a person approved the call (false once a middleware changed the arguments)
}
```

`afterRun` is called once a run finished and its writes to memory settled, before `run()` returns. It is not called for a run that failed or paused, and an error it throws is logged without failing the run.

`RunMiddlewareContext` carries `runId`, `threadId`, `agentId`, `agentName`, `userId`, `channelType`, `channelId`, `iteration`, `signal`, `deps` and a `state` map the run's middleware share. See [Run Middleware](/docs/core/middleware).

## Tool Types

```typescript
interface Tool<TParams = unknown, TResult = unknown, TDeps = unknown> {
  name: string;
  title?: string; // name for people, such as an MCP client shows
  description: string;
  category?: ToolCategory;
  tags?: string[];
  parameters: ZodType<TParams>;
  outputSchema?: ZodType<TResult>; // not checked in a run, MCPServer advertises it
  annotations?: ToolAnnotations;
  execute(params: TParams, context: BaseToolContext<TDeps>): Promise<TResult>;
  sideEffects?: SideEffectType[];
  requiresApproval?: boolean | ApprovalCheck;
  timeout?: number;
  sandbox?: SandboxConfig;
  maxResultLength?: number; // characters of a result the model reads, over limits.maxToolResultLength
  providerTypes?: ProviderToolTypes; // sent to that provider instead of the schema
  toJSON(): ToolSchema;
}

interface ToolConfig<TParams = unknown, TResult = unknown, TDeps = unknown> {
  name: string;
  title?: string;
  description: string;
  category?: ToolCategory;
  tags?: string[];
  parameters: ZodType<TParams>;
  outputSchema?: ZodType<TResult>;
  annotations?: ToolAnnotations;
  execute: (params: TParams, context: ToolContext<TDeps>) => Promise<TResult>;
  sideEffects?: SideEffectType[];
  requiresApproval?: boolean | ((params: TParams) => boolean);
  timeout?: number;
  sandbox?: SandboxConfig;
  maxResultLength?: number;
  providerTypes?: ProviderToolTypes;
}

// The tool's type in a provider's own catalog, such as { anthropic: 'memory_20250818' }
interface ProviderToolTypes {
  anthropic?: string;
}

type ApprovalCheck = (params: Record<string, unknown>) => boolean;

// MCP tool annotations without the title, see Tool.title
interface ToolAnnotations {
  readOnlyHint?: boolean; // does not change its environment
  destructiveHint?: boolean; // may make destructive updates (when not read-only)
  idempotentHint?: boolean; // a repeated call with the same arguments has no further effect
  openWorldHint?: boolean; // reaches external entities, such as the web
}

type ToolCategory =
  | 'math'
  | 'text'
  | 'file'
  | 'network'
  | 'system'
  | 'utility'
  | 'web'
  | 'database'
  | 'communication'
  | 'development';

type SideEffectType = 'filesystem' | 'network' | 'database' | 'process' | 'external';

interface BaseToolContext<TDeps = unknown> {
  agentId: string;
  runId: string;
  signal: AbortSignal;
  toolCallId?: string;
  threadId?: string;
  userId?: string;
  channelType?: string;
  channelId?: string;
  deps?: TDeps; // RunOptions.deps
}

// ToolContext<AppDeps> has deps present and typed, for tools that read them
type ToolContext<TDeps = unknown> = unknown extends TDeps
  ? BaseToolContext
  : BaseToolContext<TDeps> & { deps: TDeps };

interface ToolCall {
  id: string;
  name: string;
  arguments: Record<string, unknown>;
  thoughtSignature?: string; // provider reasoning signature, echoed back as-is (Gemini)
  replay?: ToolCallReplayState; // opaque provider state replayed with the call (OpenAI Responses reasoning items)
}

interface ToolCallReplayState {
  itemId?: string; // provider id of the output item that carried the call (e.g. `fc_...`)
  precedingItems?: Record<string, unknown>[]; // e.g. reasoning items with encrypted_content, sent back verbatim
}

interface ToolResult {
  callId: string;
  name: string;
  result: unknown;
  error?: string;
}

interface ToolSchema {
  name: string;
  description: string;
  parameters: {
    type: 'object';
    properties: Record<string, unknown>;
    required?: string[];
  };
  providerTypes?: ProviderToolTypes; // sent to that provider instead of parameters
}
```

A tool that returns media or more than one value returns a `ToolContentResult`, built with `toolContent()` from `@cogitator-ai/core` (see [Media Results](/docs/core/tools#media-results-with-toolcontent)):

```typescript
interface ToolContentResult {
  type: 'tool-content';
  content: ToolContentPart[];
}

type ToolContentPart =
  ToolTextPart | ToolImagePart | ToolFilePart | ToolJsonPart | ToolResourcePart;

interface ToolTextPart {
  type: 'text';
  text: string;
}

interface ToolImagePart {
  type: 'image';
  data: string; // base64, without a data: URL prefix
  mediaType: string; // e.g. image/png
}

interface ToolFilePart {
  type: 'file';
  data: string; // base64, the model reads only a description
  mediaType: string; // e.g. audio/mpeg
  filename?: string;
}

interface ToolJsonPart {
  type: 'json';
  value: unknown; // the model reads it as JSON text
}

interface ToolResourcePart {
  type: 'resource';
  uri: string; // e.g. file:///repo/README.md
  name?: string;
  description?: string;
  mediaType?: string;
  text?: string; // the model reads it
  data?: string; // base64, stays with the application, at most one of text and data
}
```

The package also holds the helpers that read such results, with no dependencies, so packages without `@cogitator-ai/core` read them the same way a run does: `isToolContentResult(value)`, `toolResultParts(result)` (the parts of a `ToolContentResult` or of an object with a base64 `image` or `imageBase64`), `toolPartsToText(parts)` (the text the model reads, images and files described), `truncateToolResultText(text, maxLength)` and `DEFAULT_TOOL_RESULT_MAX_LENGTH` (100 000). Core re-exports all of them.

The tool cache types (`WithCacheOptions`, `CachedTool`, `CacheStats`, `ToolCacheStorage`, `RedisClientLike`, `DurationString`) are described on [Tool Caching](/docs/tools/tool-caching).

## Message Types

```typescript
type MessageRole = 'system' | 'user' | 'assistant' | 'tool';

type MessageContent = string | ContentPart[];

type ContentPart =
  | { type: 'text'; text: string }
  | { type: 'image_url'; image_url: { url: string; detail?: 'auto' | 'low' | 'high' } }
  | {
      type: 'image_base64';
      image_base64: {
        data: string;
        media_type: 'image/jpeg' | 'image/png' | 'image/gif' | 'image/webp';
      };
    };

interface Message {
  role: MessageRole;
  content: MessageContent;
  name?: string;
  toolCallId?: string;
  cacheBreakpoint?: boolean; // ends a part of the prompt the next turns send again unchanged
}

interface ToolCallMessage extends Message {
  role: 'assistant';
  content: string;
  toolCalls: ToolCall[];
}

interface ToolResultMessage extends Message {
  role: 'tool';
  content: string;
  toolCallId: string;
  name: string;
}
```

The three content parts are exported as `TextContentPart`, `ImageUrlContentPart` and `ImageBase64ContentPart`.

`cacheBreakpoint` marks the end of a stable part of the prompt, such as the history a [context](/docs/memory#message-order-and-prompt-caching) was built from. Backends that mark Anthropic's prompt cache (Anthropic, and Claude through OpenRouter) put a cache breakpoint at the end of the last message that carries it, other backends ignore it.

## Configuration Types

```typescript
interface CogitatorConfig {
  llm?: {
    defaultProvider?: LLMProvider; // for model strings without a known provider prefix; default 'ollama'
    defaultModel?: string;
    providers?: LLMProvidersConfig;
    backends?: Record<string, LLMBackend>; // your own backends by name; a built-in name replaces it
    plugins?: Record<string, unknown>; // config for registerLLMBackend plugins, by provider
    retry?: LLMRetryConfig | false; // on by default
    promptCache?: PromptCacheConfig | false; // on by default
    modelCircuitBreaker?: ModelCircuitBreakerConfig; // when a failing fallbackModels model is skipped
    pricing?: Record<string, ModelPriceConfig>; // USD per million tokens, by model string or its tail after any '/'
  };
  runCheckpoints?: RunCheckpointStore; // where paused runs wait
  prompts?: PromptsConfig; // instruction versions and A/B tests
  middleware?: RunMiddleware[]; // hooks around every run's model and tool calls, and invokeTool()
  limits?: {
    maxConcurrentRuns?: number;
    defaultTimeout?: number;
    maxTokensPerRun?: number;
    maxToolResultLength?: number; // characters of a tool result the model reads (default 100000)
  };
  memory?: MemoryConfig;
  sandbox?: SandboxManagerConfig;
  reflection?: ReflectionConfig;
  guardrails?: Partial<GuardrailConfig>; // on unless enabled: false
  costRouting?: CostRoutingConfig;
  security?: {
    promptInjection?: Partial<PromptInjectionConfig>;
    pii?: PiiConfig;
  };
  context?: ContextManagerConfig;
  logging?: LoggingConfig;
  deploy?: DeployConfig;
}

interface PromptsConfig {
  versions?: InstructionVersionStore; // default: in process memory
  abTests?: ABTestStore; // default: in process memory
  score?: (result: RunResult) => number | Promise<number>; // default: 1
  autoDeployWinner?: boolean;
}

interface PiiConfig {
  mode?: 'mask' | 'redact' | 'block';
  detect?: PiiType[]; // default: all built-in kinds
  custom?: Array<{ type: string; pattern: RegExp }>;
  onDetect?: (counts: Record<string, number>) => void;
}

interface LoggingConfig {
  level?: 'debug' | 'info' | 'warn' | 'error' | 'silent'; // default: 'info'
  format?: 'json' | 'pretty'; // default: 'pretty' ('json' for files)
  destination?: 'console' | 'file'; // default: 'console'
  filePath?: string; // required for 'file'
}
```

`logging` configures the process-wide logger (`getLogger()` from `@cogitator-ai/core`), so the last `Cogitator` created with `logging` sets it for every runtime in the process. `'silent'` outputs nothing; `destination: 'file'` appends one line per entry to `filePath` (JSON lines unless `format` is set) and falls back to the console, with a warning, when `filePath` is missing or the runtime has no file system.

## Memory Types

```typescript
type MemoryResult<T> = { success: true; data: T } | { success: false; error: string };

type MemoryProvider = 'memory' | 'redis' | 'postgres' | 'sqlite' | 'mongodb' | 'qdrant';
```

`MemoryAdapter.redactEntry?(entryId, redaction: EntryRedaction)` replaces what a `message` or `tool_result` entry said with `[redacted]` in place (its text, the arguments, replay state and argument error of its tool calls, the results of its tools, and the sender `name` of a user message), keeps its parent, role and call ids, records the redaction in `metadata.redacted` (`{ at, reason? }`, `at` as an ISO string), and refuses an event entry. `forkThread?` lists the fork in the origin's `metadata.memoryForks` and does not copy its paused run. The [context builder](/docs/memory#context-building) shares its budget among partitions and reports what it left out with these types:


`ContextBuilderConfig` takes `partitions?: Partial<Record<ContextPartition, ContextPartitionBudget>>`, merged over the defaults (`system`, `pinned`, `index`, `summaries`, `brief` and `final` required, `facts` 15%, `recall` 35%, `recent` the rest, shares of the partitions that are not required adding up to 1 at most), `BuiltContext` has `memoryContext?: string` (what changes every turn, sent with the input) and `partitions` (tokens per partition), and `DroppedContext` has `blocks: DroppedBlock[]`.

`cog.run()` throws a `CogitatorError` when a run hits its `timeout` (`Run timed out after <n>ms`, `RUN_TIMEOUT`), when cost routing finds the budget exceeded (`Budget exceeded: …`, `BUDGET_EXCEEDED`), and when guardrails block the input or output (`Input blocked: …` / `Output blocked: …`, `LLM_CONTENT_FILTERED`, with `details.harmScores`), so server adapters answer with that status and message.

`ERROR_STATUS_CODES` maps each code to an HTTP status (for example `RUN_TIMEOUT` → 504, `BUDGET_EXCEEDED` → 429, `LLM_CONTENT_FILTERED` → 400, `LLM_QUOTA_EXCEEDED` → 402), `isRetryableError(error)` and `getRetryDelay(error, defaultDelay = 1000)` read `retryable` / `retryAfter` (and treat plain errors mentioning timeouts, connection resets, rate limits, 429 or 503 as retryable).
