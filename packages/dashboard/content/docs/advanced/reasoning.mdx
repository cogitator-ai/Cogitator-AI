## Overview

Tree-of-Thought (ToT) reasoning lets an agent explore several approaches to a problem, score each one, drop the weak ones and keep the best result. Instead of committing to a single chain of thought, the `ThoughtTreeExecutor` builds a tree of candidate approaches and runs the promising ones as ordinary agent runs.

This page is about that executor. A model's own built-in thinking (OpenAI reasoning effort, Claude extended thinking, Gemini thinking budgets) is set with the `reasoning` option of an agent or a run — see [Reasoning](/docs/core/llm-backends#reasoning) under LLM backends. The two combine: the runs inside a tree use the agent's `reasoning` setting like any other run.

## Basic Usage

```typescript
import { Agent, Cogitator, ThoughtTreeExecutor } from '@cogitator-ai/core';

const cogitator = new Cogitator({
  llm: {
    defaultProvider: 'openai',
    providers: { openai: { apiKey: process.env.OPENAI_API_KEY! } },
  },
});

const executor = new ThoughtTreeExecutor(cogitator, {
  maxDepth: 4,
  branchFactor: 3,
  beamWidth: 2,
  confidenceThreshold: 0.3,
  terminationConfidence: 0.9,
  maxTotalNodes: 50,
});

const agent = new Agent({
  name: 'problem-solver',
  instructions: 'You solve complex problems by exploring multiple approaches.',
  model: 'gpt-6.1-sol',
});

const result = await executor.explore(agent, 'Design a caching strategy for a real-time dashboard');

console.log('Success:', result.success);
console.log('Output:', result.output);
console.log('Best path depth:', result.bestPath.length);
console.log('Nodes explored:', result.stats.exploredNodes);
```

The executor makes its own model calls — branch generation, branch evaluation and the final synthesis — with the backend of the agent's model, and sends the agent's model string to it as is. Give the agent a bare model name served by `llm.defaultProvider`, as above: a `provider/model` id would reach the provider with its prefix.

## How It Works

1. **Root** — the goal becomes the root node.
2. **Branch generation** — the `BranchGenerator` asks the model for `branchFactor` candidate approaches for the node, each a `thought` with a proposed action: a tool call, a sub-goal or a direct response.
3. **Branch evaluation** — the `BranchEvaluator` scores every candidate on confidence, progress and novelty, combined into a `composite` score.
4. **Pruning** — candidates with a composite score below `confidenceThreshold` are dropped, and at most `beamWidth` of the rest are kept.
5. **Expansion** — each kept candidate becomes a child node. A direct response is taken as is; a tool call or sub-goal runs the agent with `cogitator.run()` (without memory) on a prompt built from the goal and the approach.
6. **Termination** — exploration stops as soon as a child's branch confidence reaches `terminationConfidence`, or when the frontier is empty, `maxTotalNodes` nodes exist, the `timeout` passes or the abort signal fires. Nodes at `maxDepth` are not expanded further.
7. **Result** — the node with the highest cumulative score (the sum of composite scores along its path) wins. Its answer is the output; without one, the path is synthesized into a final answer with one more model call.

Expanded nodes go back into the frontier, which is ordered by cumulative score.

## Configuration

```typescript
const executor = new ThoughtTreeExecutor(cogitator, {
  maxDepth: 5, // how deep the tree can grow (default 5)
  branchFactor: 3, // candidates generated per node (default 3)
  beamWidth: 2, // candidates kept per node (default 2)
  confidenceThreshold: 0.3, // minimum composite score to keep a candidate (default 0.3)
  terminationConfidence: 0.8, // branch confidence that stops the search (default 0.8)
  maxTotalNodes: 50, // hard cap on expanded nodes (default 50)
  timeout: 60_000, // ms, optional
});
```

Higher `branchFactor` explores more possibilities but costs more tokens. Lower `beamWidth` focuses the search but risks missing good paths. `DEFAULT_TOT_CONFIG` holds the defaults.

## Callbacks

```typescript
const executor = new ThoughtTreeExecutor(cogitator, {
  onBranchGenerated: (node, branches) =>
    console.log(`${branches.length} ideas at depth ${node.depth}`),
  onBranchEvaluated: (branch, score) => console.log(branch.thought, score.composite),
  onNodeExplored: (node) => console.log(node.status, node.result?.response),
  onBacktrack: (from, to) => console.log(`Dead end at depth ${from.depth}`, to?.depth ?? 'none'),
});
```

`onBacktrack` fires when every candidate of a node scores below the threshold, or when running a node fails; the node is marked `failed`.

## Branch Generation

The `BranchGenerator` can be used on its own. It takes a backend and the model name to send to it:

```typescript
import { BranchGenerator } from '@cogitator-ai/core';

const generator = new BranchGenerator(llmBackend, 'gpt-6.1-sol');

const branches = await generator.generate(
  currentNode, // null for the root
  'Optimize database query performance',
  3,
  agentContext,
  exploredThoughts
);
```

Each branch has a `thought`, a `proposedAction` and the parent node's messages. Previously explored thoughts are passed in to encourage novelty. When the model's answer cannot be parsed, generic fallback branches are returned.

## Branch Evaluation

The `BranchEvaluator` scores branches on three dimensions:

- **Confidence** — how likely is this approach to succeed?
- **Progress** — how much closer does it get to the goal?
- **Novelty** — how different is it from sibling branches?

```typescript
import { BranchEvaluator } from '@cogitator-ai/core';

const evaluator = new BranchEvaluator({
  llm: llmBackend,
  model: 'gpt-6.1-sol',
  reflectionEngine, // optional
  confidenceWeight: 0.5,
  progressWeight: 0.3,
  noveltyWeight: 0.2,
});

const scores = await evaluator.evaluateBatch(branches, goal, agentContext);
```

The weights above are the defaults for the composite score. When a `ReflectionEngine` is given, tool-call branches are evaluated with the agent's past insights. Inside `explore()`, the Cogitator's reflection engine is used when [reflection](/docs/advanced/reflection) is enabled and has been initialized by an earlier run.

## Progress Monitoring

```typescript
const controller = new AbortController();

const result = await executor.explore(agent, goal, {
  timeout: 30_000,
  abortSignal: controller.signal,
  onProgress: (stats) => {
    console.log(`Explored: ${stats.exploredNodes}/${stats.totalNodes}`);
    console.log(`Depth: ${stats.maxDepthReached}, Backtracks: ${stats.backtrackCount}`);
    console.log(`LLM calls: ${stats.llmCalls}`);
  },
});
```

`onProgress` is called after each node's candidates have been expanded. On timeout or abort, the best node found so far is returned.

## Result Structure

```typescript
interface ToTResult {
  success: boolean;
  output: string;
  tree: ThoughtTree;
  bestPath: ThoughtNode[];
  stats: ToTStats;
  runId: string;
  agentId: string;
  usage: {
    inputTokens: number;
    outputTokens: number;
    totalTokens: number;
    cost: number;
    duration: number;
  };
}
```

`bestPath` holds every node from the root to the winning node, so you can trace how the agent reached its conclusion; the full `tree` (with `nodes` as a `Map`) is there for visualization or debugging. `success` is true when the winning node completed. `usage` counts the tokens of the agent runs inside the tree, not those of generation and evaluation calls, and `cost` is not computed (always 0).

## When to Use ToT

Tree-of-Thought reasoning is most effective for:

- Problems with multiple valid approaches (architecture decisions, optimization)
- Tasks where the first attempt often fails (complex debugging, multi-step reasoning)
- Situations where exploring alternatives has high value (research, strategy)

For straightforward tasks, a single run — possibly with the model's own `reasoning` turned up — is faster and cheaper. Use ToT when the cost of exploring is worth the improvement in output quality.
