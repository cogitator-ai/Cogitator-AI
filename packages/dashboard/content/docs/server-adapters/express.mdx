---
title: Express Adapter
description: Serve your Cogitator agents over HTTP with Express.js — class-based setup with middleware, SSE streaming, and WebSocket support.
---

The `@cogitator-ai/express` package provides `CogitatorServer`, a class that mounts a full REST API onto your existing Express router. It handles JSON parsing, authentication, rate limiting, CORS, error handling, Swagger docs, and WebSocket support out of the box.

## Installation

```bash
pnpm add @cogitator-ai/express express
```

## Basic Setup

```typescript
import express from 'express';
import { Cogitator, Agent, tool } from '@cogitator-ai/core';
import { CogitatorServer } from '@cogitator-ai/express';
import { z } from 'zod';

const app = express();

const cogitator = new Cogitator({
  llm: {
    defaultModel: 'openai/gpt-4o',
    providers: {
      openai: { apiKey: process.env.OPENAI_API_KEY! },
    },
  },
});

const search = tool({
  name: 'web_search',
  description: 'Search the web',
  parameters: z.object({ query: z.string() }),
  execute: async ({ query }) => ({ results: [`Result for: ${query}`] }),
});

const assistant = new Agent({
  name: 'assistant',
  description: 'Assistant with web search',
  model: 'openai/gpt-4o',
  instructions: 'You are a helpful assistant with web search capabilities.',
  tools: [search],
});

const server = new CogitatorServer({
  app: app,
  cogitator,
  agents: { assistant },
  config: {
    basePath: '/cogitator',
    enableSwagger: true,
    enableWebSocket: false,
  },
});

await server.init();

app.listen(3000, () => {
  console.log('Server running on http://localhost:3000');
  console.log('Swagger UI: http://localhost:3000/cogitator/docs');
});
```

## Configuration

The `CogitatorServerConfig` interface accepts:

```typescript
interface CogitatorServerConfig {
  app: Router;
  cogitator: Cogitator;
  agents?: Record<string, Agent>;
  workflows?: Record<string, Workflow>;
  swarms?: Record<string, SwarmConfig>;
  config?: {
    basePath?: string; // default: '/cogitator'
    enableWebSocket?: boolean; // default: false
    enableSwagger?: boolean; // default: true
    auth?: AuthFunction;
    rateLimit?: RateLimitConfig;
    cors?: CorsConfig;
    swagger?: SwaggerConfig;
    websocket?: WebSocketConfig;
  };
}
```

## Request Handling

- Agent and swarm bodies are validated: `input` must be a non-empty string, `context` an object, `threadId` a string, swarm `timeout` a positive number. Invalid or malformed JSON bodies return `400 INVALID_INPUT`.
- Workflow `options` are limited to `maxConcurrency`, `maxIterations` (positive integers) and `checkpoint` (boolean); other options are dropped and wrongly typed ones return `400`.
- Thread messages need a `role` of `user`, `assistant` or `system` and a non-empty string `content`.
- A workflow that fails returns `500 WORKFLOW_FAILED`, and its stream ends with an `error` event instead of `workflow_completed`.
- `CogitatorError`s keep their code and mapped status (for example `LLM_RATE_LIMITED` → 429); other errors return a generic `500 INTERNAL` and are logged.
- `GET /agents` exposes each agent's `config.description`, never its `instructions`.

## Authentication

Pass a custom `auth` function that receives the Express request and returns an `AuthContext`:

```typescript
const server = new CogitatorServer({
  app,
  cogitator,
  agents: { assistant },
  config: {
    auth: async (req) => {
      const token = req.headers.authorization?.replace('Bearer ', '');
      if (!token) return undefined;

      const user = await verifyToken(token);
      return { userId: user.id, roles: user.roles };
    },
  },
});
```

When `auth` returns `undefined`, the request proceeds as unauthenticated; throw to reject it with `401`. The `AuthContext` is attached to `req.cogitator.auth`, its `userId` is passed to agent runs, and the same function guards WebSocket upgrade requests.

## Rate Limiting

```typescript
config: {
  rateLimit: {
    windowMs: 60_000,
    max: 100,
    message: 'Too many requests',
    keyGenerator: (req) => req.ip ?? 'unknown',
    trustProxy: false, // true: key by the nearest X-Forwarded-For hop (the address your proxy saw)
  },
}
```

The limiter is in-memory and per process; `windowMs` must be positive and `max` non-negative, otherwise creating the middleware throws. Requests without a client address share a single bucket.

## CORS

```typescript
config: {
  cors: {
    origin: ['https://app.example.com'],
    credentials: true,
    methods: ['GET', 'POST', 'DELETE'],
  },
}
```

`credentials` defaults to `true` for explicit origins and to `false` for `origin: '*'` (plain `Access-Control-Allow-Origin: *`). Setting `credentials: true` together with `'*'` reflects every origin with credentials — only do that deliberately. Disallowed origins get no CORS grants, including on preflight.

## Streaming

The `/agents/:name/stream` endpoint returns an SSE stream: `start`, `text-start`/`text-delta`/`text-end` blocks, `tool-call-start`/`tool-call-delta`/`tool-call-end` (the id is the model's tool call id, matching `tool-result.toolCallId`), `tool-result`, then `finish` and `[DONE]` — or an `error` event. Disconnecting aborts the run. Read it with `fetch` (EventSource cannot send a POST body):

```typescript
const response = await fetch('http://localhost:3000/cogitator/agents/assistant/stream', {
  method: 'POST',
  headers: { 'Content-Type': 'application/json' },
  body: JSON.stringify({ input: 'Explain quantum computing' }),
});

const reader = response.body!.getReader();
const decoder = new TextDecoder();

while (true) {
  const { done, value } = await reader.read();
  if (done) break;
  console.log(decoder.decode(value));
}
```

## WebSocket

WebSocket support requires the `ws` package. Enable it, then attach it to your HTTP server after `init()`:

```typescript
import { createServer } from 'http';

const server = new CogitatorServer({
  app,
  cogitator,
  agents: { assistant },
  config: { enableWebSocket: true },
});
await server.init();

const httpServer = createServer(app);
await server.attachWebSocket(httpServer); // ws://host/cogitator/ws
httpServer.listen(3000);
```

Run an agent (only agent runs are supported over WebSocket):

```json
{
  "type": "run",
  "id": "req_1",
  "payload": { "type": "agent", "name": "assistant", "input": "Hello" }
}
```

Events arrive as `{ "type": "event", "id": "req_1", "payload": { "type": "token" | "tool-call" | "tool-result" | "complete" | "cancelled", ... } }`. Send `{ "type": "stop" }` to abort the running agent. Subscribe to `agent:<name>` (`{ "type": "subscribe", "channel": "agent:assistant" }`) to observe runs started by other clients.
